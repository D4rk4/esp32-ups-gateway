# Драйверы последовательного протокола

В этой версии реализован один профиль: `megatec_q1`. Его метка намеренно сообщает, что совместимость с конкретным Inform Sinus EVO требует проверки. Драйвер реализует документированное семейство MegaTec; бинарный код KPM220 не используется.

## Файлы и границы

| Файл | Ответственность |
|---|---|
| `lib/UpsCore/src/ups_model.hpp` | Нормализованное состояние, признаки валидности, команды, параметры UART и capabilities |
| `lib/UpsCore/src/ups_driver.hpp` | Абстрактный контракт `UpsDriver` |
| `lib/UpsCore/src/megatec_q1.hpp/.cpp` | Формирование Q1/F/I, определение границ ответа, разбор MegaTec, кодирование команд |
| `lib/UpsCore/src/driver_registry.hpp/.cpp` | Список драйверов и поиск по устойчивому id |
| `src/ups_service.cpp` | Единственный владелец UART, таймауты, свежесть, очередь управления |
| `lib/GatewayCore/src/powernet_mib.cpp` | Представление нормализованных значений через PowerNet |

`UpsCore` не зависит от Arduino, веб-сервера или UDP и тестируется обычным C++17-компилятором.

## Контракт

- `info()` возвращает неизменяемые `DriverInfo`: id, label, default_baud, capabilities, parity, stop_bits. Формат данных UART сейчас фиксирован как 8 бит; поддерживаются None/Even/Odd и 1/2 stop bits. Рабочая скорость берётся из сохранённого `Config::baud`, поэтому при смене профиля её нужно настроить отдельно.
- `buildPoll(PollKind, bytes)` формирует полный запрос, включая терминатор или контрольную сумму. Отсутствующий необязательный Rating/Identity возвращает false и пустые bytes.
- `maxReplyLength()` ограничивает буфер одного ответа, включая терминатор. Он должен быть конечным и достаточным для протокола.
- `frameComplete(kind, buffer, idle_ms)` принадлежит драйверу. UART передаёт исходные байты без удаления NUL, CR или старших битов. Поэтому будущий драйвер может определять кадр по длине, терминатору, заголовку или паузе, а затем проверить CRC в парсере. Это возможность интерфейса, а не реализация нового протокола.
- `parseReply(kind, line, state)` возвращает Accepted, Ignored или Invalid. На Invalid/Ignored состояние должно оставаться неизменным. Разбор выполняется в копию с фиксацией только после проверки всего кадра.
- `encodeCommand(command, args, out, error)` проверяет возможности/диапазоны и формирует байты. Поле `changes_output` включает дополнительное разрешение силовых операций. `settle_ms` задаёт паузу перед следующим опросом.

Драйвер не меняет `connected`, `last_success_ms`, счётчики ошибок/успешных опросов и не отправляет сетевые события. Эти данные принадлежат `UpsService`. Успех F/I не продлевает свежесть Q1. После потери связи SNMP публикует состояние связи/unknown, а устаревшие измерения исключает.

Текущий контракт команд подтверждает только передачу байтов: результат в веб-интерфейсе — `sent_unconfirmed`. Ответы на управляющие команды не интерпретируются как отдельная транзакция ACK. Для будущего протокола, требующего командного подтверждения или многошагового handshake, нужно расширить контракт и `UpsService`, а не выдавать факт записи UART за выполненную операцию.

## Что умеет профиль MegaTec Q1

Используются Q1 для состояния, F для номиналов, I для идентификации. Граница ASCII-кадра — CR или LF; предел ответа 160 байт. Поля I имеют фиксированную ширину. Эхо запросов и распознанный NAK игнорируются; повреждённые/обрезанные строки отклоняются без частичного обновления. Маркеры отсутствующего значения из `@` сбрасывают validity соответствующего измерения.

Нормализуются входное и аварийное входное напряжение, выходное напряжение, нагрузка в процентах, входная частота, сырое напряжение батареи, температура UPS и биты состояния. Бит bypass/AVR означает Bypass только для online-топологии. Признак shutdown-active не означает, что выход уже отключён.

Q1 не даёт процентов заряда, оставшегося времени, измеренной выходной частоты, серийного номера, результата самотеста или признака замены батареи. Эта версия их не выдумывает. Общая неисправность и завершение теста попадают в локальный журнал, но не превращаются в неподтверждённый APC trap «тест провален/пройден».

`upsAdvBatteryTemperature` / high-precision counterpart по описанию PowerNet означают внутреннюю температуру UPS, несмотря на слово Battery в историческом имени. Поэтому `ups_temperature` корректно отображается в этих объектах. Отдельное `battery_temperature` в модели оставлено для протокола, который действительно сообщает температуру батареи. См. описание объектов в [APC PowerNet-MIB](https://raw.githubusercontent.com/librenms/librenms/master/mibs/apc/PowerNet-MIB).

Батарейный множитель применяется службой после разбора сырого значения; 0 означает «масштаб не подтверждён». Запрещено заменять отсутствующий runtime нулём или копировать номинальную частоту F в измеренную выходную частоту.

Управление: переключение зуммера, короткий тест, отмена теста, отмена shutdown, задержанное выключение и перезапуск выхода. Выключение допускает задержку 1–10 минут; перезапуск — восстановление через 3–9999 минут. Тест до полного разряда не включён. Оба разрешения управления по умолчанию выключены. Поддержка команд семейством протокола не является стендовой проверкой конкретного ИБП.

Источники поведения: [описание MegaTec](https://networkupstools.org/protocols/megatec.html), [NUT blazer.c](https://github.com/networkupstools/nut/blob/master/drivers/blazer.c). Реализация проекта написана самостоятельно по протоколу.

## Добавление подтверждённого диалекта

1. Сохраните обезличенные реальные ответы и описание протокола. Отдельно определите поля, единицы, CRC/границы, необязательные ответы и семантику управления.
2. Добавьте класс-наследник в `lib/UpsCore/src/`. Не изменяйте действующий MegaTec для несовместимых пакетов.
3. Сначала добавьте host-тесты в `tests/test_<driver>.cpp`: корректные значения, каждый бит, частичные кадры, неверный CRC/длина, эхо, таймаутная граница, неизвестные значения, атомарность отказа и точные управляющие байты.
4. Реализуйте все методы `UpsDriver`. Указывайте `Metric::valid=true` только для данных, смысл которых установлен. Не переиспользуйте существующий флаг для похожей по названию, но иной аварии.
5. Зарегистрируйте статический экземпляр в `drivers()` в `driver_registry.cpp`; id после выпуска не переименовывайте, он хранится в конфигурации. Профиль автоматически появится в списке веб-интерфейса.
6. Если нужны дополнительные поля, команды или события, согласованно расширьте модель, службу, веб-API, PowerNet-отображение и тесты. Не придумывайте APC OID для отсутствующей семантики.
7. Выполните `python3 tools/test_host.py` после установки зависимостей проекта; затем `pio run -e esp32-poe-16mb`. Host-тесты не заменяют стендовые проверки UART, таймингов и управляющих функций.

Драйвер конфигурируется до старта службы. Изменённые настройки применяются после перезагрузки шлюза. Переинициализация UART во время чужого SNMP/HTTP-запроса не выполняется.
